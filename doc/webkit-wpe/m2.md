# M2 standalone EPUB backend

This M2 implementation extends the M1 worker independently of the Qt reader.
It adds reflowable EPUB opening, spine pagination, CPU page frames, chapter and
link navigation, appearance changes and provisional logical locations. CREngine
and saved reading data are unchanged. The user authorized committing this M2
implementation. Its validation scope and advanced layout limits are recorded
below; M3 integration remains a separate milestone.

The base is `feature/webkit-wpe-m1` at `15dfb82`. Changes remain on
`feature/webkit-wpe-m2`. This work does not authorize a release publication.

## Publication and resource ownership

The existing publication code was inspected before implementation.
`Publication` depends on Qt, CREngine font validation and localized application
errors; the native resource adapter depends on Nickel and its loopback service.
Linking those into this helper would break M1's library boundary. The small
helper-side `Epub` reader instead uses libxml2, GLib and zlib already in the
private runtime closure. It follows the existing archive/resource budgets and
reuses the checked-in general reading fixture. A future application caller can
supply an accepted local EPUB without changing this helper into a Nickel client.

Archive members are never extracted. Opening bounds the ZIP directory to 4 MiB,
its entries to 4096, the archive to 1 GiB and aggregate declared expansion to
4 GiB. Individual compressed and expanded resources are bounded to 16 MiB;
package/container/navigation XML is additionally limited to 2 MiB. Local headers,
compression, bounds, expanded length and CRC must agree. Duplicate, ambiguous or
unsafe member names and unsupported/encrypted ZIP entries are rejected. Reads
check file identity and modification/change times against the inspected archive.
Metadata XML never loads external DTDs or substitutes entities, and internal
DTD declarations are rejected. IDPF (SHA-1 / first 1040 bytes) and Adobe
(UUID / first 1024 bytes) font obfuscation are decoded only for declared font
resources, after validating their stored ZIP CRC. The source archive is unchanged.
Missing/ambiguous identifier keys, duplicate targets, content encryption, unknown
algorithms and LCP licenses are rejected. The IDPF key removes XML whitespace
from the unique identifier, as specified by [EPUB OCF](https://idpf.org/epub/301/spec/epub-ocf.html#sec-resource-obfuscation).

The manifest is the resource allowlist. XHTML, CSS, supported images and fonts
are served with explicit MIME headers; scripts, objects, multimedia and undeclared
members are refused. Every opening has a fresh URI authority, so requests and
links belonging to a previous publication cannot read its replacement. Relative
paths, percent escapes and fragments are resolved within the archive. External
URLs, queries, absolute filesystem paths and escapes above its root are rejected.

EPUB 3 navigation and basic EPUB 2 NCX links are exposed in the frame metadata.
Normal chapter transitions skip `linear="no"` entries; explicit spine jumps and
links can still reach them. Link destinations must belong to the spine.

## Script and network policy

`enable-javascript-markup` is disabled. Book script tags and event attributes do
not run; the JavaScriptCore API remains available to the native caller. Only the
installed `reader.js` bridge runs in the named `kobalt-reader` isolated world.
A trusted user script installed through `WebKitUserContentManager` retains that
world for the document lifetime; native calls invoke its pagination function.
Temporary evaluations alone released the named world between calls while their
DOM overrides survived. Retaining it fixes stale styles and lets each reflow
restore exact publisher inline declarations before resolving the cascade again.
Book content cannot supply or replace the function body or access its globals.

Each EPUB response also carries a restrictive Content Security Policy. It allows
only manifest resources through the private EPUB scheme, inline CSS and image/font
data URLs. Scripts, connections, frames, objects, multimedia, forms and book base
URLs are denied. Native navigation policy permits only the spine document
requested by the current operation and rejects refreshes, external navigation
and new windows. Permission requests are denied. The fixture-only M1 scheme is
outside the EPUB content policy.

The hostile runtime fixture includes inline/external scripts, a load handler,
remote stylesheet import, remote image, iframe and meta refresh. A loopback HTTP
listener records attempted requests while VirtualNickel keeps its normal external
network restrictions. This content policy supplements WebKit's sandbox; it does
not establish process isolation. M1's required-sandbox default and explicit
experimental/device modes are unchanged. Physical sandbox validation remains open.

## Pagination, appearance and locations

The trusted bridge uses single-page horizontal CSS columns, constrained images,
viewport margins and a page-sized translation. It waits for font selection,
font loading, image decoding and animation-frame completion before measuring and
capturing. Forced font selection before `document.fonts.ready` avoids resolving
the promise before new styles request their fonts.

Legacy `page-break-before/after: always` and modern forced page breaks are
translated from their winning computed values into column breaks. Generic
`avoid` rules remain; page-specific avoidance becomes column avoidance. The
bridge applies a bounded geometry correction for fitting normal-flow sibling
groups joined by avoid-before/after boundaries, which this WebKit column layout
does not otherwise enforce. Groups too large for a page can still split. Forced
breaks win over avoidance. Publisher selectors and source DOM structure stay
intact. Nested chapter/heading breaks before the first visible text or image are
suppressed so leading margins, empty spacer divs and line breaks do not create
spurious blank chapter pages.

`left`, `right`, `recto` and `verso` force the next reader page in this single-page
view. They do not insert parity blanks or implement facing-page spreads. That
limitation is deliberate and separately recorded. Runtime regressions cover
forced/avoided boundaries, cascade precedence, media-query changes after resize
and nested chapter-start rules.

The helper resolves `serif`, `sans-serif` and `monospace` through the firmware's
Fontconfig and supplies the actual family names to WebKit. The selected firmware
can return a fallback without the strong generic-family binding Skia expects;
using the unresolved default produced zero-height inline rectangles despite
visible fallback glyphs. The resolved families restore valid primary line metrics.
No firmware fonts are copied into the package. Another observed issue was the
need for an explicit HTTP `Content-Type` header alongside the scheme response's
MIME property when `nosniff` is enabled; otherwise EPUB stylesheets were rejected.
Both issues are covered by the runtime fixture's geometry/font checks.

Appearance includes body font size in CSS pixels, line height, margin, letter and
word spacing, publisher/serif/sans/monospace families and light/dark colors. Settings
remain in helper memory and carry across book openings; nothing is persisted.
Author styling and embedded fonts remain available in publisher mode.

Frame layout metadata reports the document URI, CSS viewport, zero-based page,
chapter page count, content rectangle, visible link/image geometry and a source-text
excerpt. The native caller rejects stale about:blank/document results during rapid
close/reopen. Text location measurement skips collapsed whitespace without mapping
it spuriously to the first column. Logical locations
contain a version, spine index and start/end offsets in the body's UTF-16 text
stream, excluding script/style/noscript text. Reflow uses the preceding source
anchor rather than the preceding page number. These are provisional locations
for this helper, **not EPUB CFI, persistent Kobalt positions or CREngine XPointer
replacements**. Image-only pages can have an empty text interval; an optional body-child element
path keeps their object anchor stable across viewport changes.

[EPUB.js layout](https://github.com/futurepress/epub.js/blob/master/src/layout.js)
and its [CFI implementation](https://github.com/futurepress/epub.js/blob/master/src/epubcfi.js)
were investigated as references. This slice uses native package handling and CSS
columns without taking an EPUB.js runtime dependency or copying its code. A
persistent backend-independent position/CFI contract remains M4 work.

## Standalone protocol additions

The M1 `KWRP/1` transport, increasing request IDs, 8192-byte request bound (increased from M1's 256 bytes), bounded
output queue, asynchronous ping and lifecycle behavior remain. Base64 arguments
are canonical UTF-8 without NULs; they must fit the existing line bound. One
rendering operation is active at a time. `PING`, `RELEASE` and `SHUTDOWN` remain
available during a render. Invalid requests return stable error codes.

| Command | Arguments and result |
| --- | --- |
| `OPEN` | Base64 absolute EPUB filename, viewport width, height. Opens and captures the first linear spine item. |
| `NEXT`, `PREVIOUS` | Move within the chapter or across linear spine entries; book boundaries return an error. |
| `GOTO` | Zero-based spine and page indices. Pages beyond the chapter end clamp to its last page. |
| `LINK` | Base64 relative href or current-publication EPUB URI; follows an optional fragment. |
| `RESIZE` | Width and height, preserving the source anchor. Each dimension is 100–2048 pixels. |
| `STYLE` | Font size (8–96 px), line height (100–300%), margin (px), letter spacing (0–50% em), word spacing (0–100% em), family (`publisher`, `serif`, `sans-serif`, `monospace`), theme (`light`, `dark`). Captures after reflow. |
| `RELEASE` | Original frame request ID. Deletes that frame's raw pixels, diagnostic PNG and metadata. |
| `CLOSE` | Releases publication state; outstanding frames retain their lifetime until released or the helper exits. |

A page-producing operation answers `KWRP/1 <id> OK PAGE <absolute-json-path>`.
That JSON describes versioned frame dimensions/stride, format, publication/spine,
layout and absolute raw-pixel/diagnostic-PNG paths. Pixels are CPU-owned,
little-endian BGRA8 with premultiplied alpha and the declared stride. Their storage
is immutable until `RELEASE`; at most two frames can remain outstanding. Readers
copy or map the raw bytes before releasing the frame. Supervisor shutdown removes
all remaining run-owned files. Shared-memory/descriptor transfer to Qt belongs
to M3; this slice makes no production IPC performance claim.

No explicit page cache or pre-rendering queue was introduced. WebKit retains its
ordinary ephemeral resource/document caching. Measurements should justify an
additional page cache before it is added.

## Build and verification

Use the pinned M1 image and shared dependency cache as documented in [M1](m1.md).
No Qt SDK or WebKit rebuild is required when only helper sources change:

```sh
bash platforms/webkit/build.sh
cd platforms/webkit
cmake --preset native-supervisor
cmake --build --preset native-supervisor
ctest --preset native-supervisor
```

The native preset now also requires the prepared native GLib/libxml2/zlib headers.
The already prepared native image documented in M1 supplies them. Firmware
verification reuses the existing Device API runner and deletes its disposable
device and volume in `finally`:

```sh
python3 tests/webkit/run-firmware.py \
  --virtualnickel /home/sherman/kobo-dev/VirtualNickel \
  --allow-unsandboxed-experiment --epub-tests
```

`--epub-tests` runs the existing M1 lifecycle checks followed by EPUB checks.
`--epub-only` selects focused EPUB checks when applicable M1 results can be reused.
The renderer always receives an explicit mode; tests never change the simulator.
Python remains simulator diagnostics, not application build tooling.

The general fixture is Kobalt's checked-in Trevelyan's Type Tester v1.2, public
domain, including the repository's chapter-heading CSS correction. Its SHA-256 is
`1050bc7af6a6b19267319c8b56965ca7cbf63abedfa8079ab5c4eacbb6c407ac`.
The source export includes it for these checks. Focused fixtures add hostile content, font-obfuscation vectors, break rules,
image-only pages and precise pagination/link assertions; they do not replace the
general book. See [M2 results](m2-results.json) for exact evidence and validation scope.

## Representative books and review limits

The firmware checks include Trevelyan plus the repository's pinned Gutenberg
Alice and Moby Dick editions, with chapter capture, navigation and stable return
images. Text-bearing literary pages also require non-uniform pixels: DOM geometry
alone previously hid a blank spacer page. Captures are inspected visually; these
are representative chapter checks, not an exhaustive EPUB conformance claim.

Prepare the literary fixtures explicitly with the existing gallery helper:

```sh
cmake '-DNAMES=alice;moby-dick' -DOUTPUT="$PWD/build/webkit/books" \
  -DREFERENCES="$PWD/tests/fixtures/screenshot-books.json" \
  -P platforms/desktop/prepare-screenshot-books.cmake
python3 tests/webkit/run-firmware.py \
  --virtualnickel /home/sherman/kobo-dev/VirtualNickel \
  --allow-unsandboxed-experiment --epub-tests --epub-corpus
```

Downloads retain the existing version/checksum pins. Ordinary builds and tests
do not fetch them automatically. The source export includes the reference
manifest and preparation helper for these optional diagnostics.

Fixed-layout publications, vertical writing and a right-to-left body remain
explicitly unsupported. Mixed-direction text inside an LTR chapter uses WebKit's
text layout. Full recto/verso spreads, nested table/flex/grid fragmentation,
advanced multilingual coverage and persistent source-position/CFI compatibility
remain later work. Internal links currently target spine documents.

A missing fragment returns `ERROR missing-link-target` after restoring the previous
chapter/page, without restarting the helper. Other failed asynchronous
layout/capture operations still end the worker as in M1. A fresh helper remains
the recovery boundary for those failures. Long UTF-8 filenames and hrefs fit the
increased bounded transport; source-path resolution still has its own 4096-byte
limit.

Physical-device ABI/kernel behavior, memory/storage costs, e-ink quality and timing
remain unverified. Runtime frame files are development transport; this change does
not justify performance or battery claims. Kobalt application suites and Kobo Qt
SDK builds were not rerun because no application/shared adapter source changed.
M2 was approved for commit. Do not start M3 without separate authorization.
