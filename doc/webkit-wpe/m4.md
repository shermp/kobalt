# M4 source positions and table of contents

This initial M4 slice builds on M3 (`bcbcfdd`) in
`feature/webkit-wpe-m4`. It adds persistent WebKit positions and connects the
publication table of contents to the existing Chapters screen. It is
approved for commit after deployment to the manual device. It does not claim
the complete M4 feature-parity gate. The screenshot round has no recorded seen
states or annotations; commit approval was given in chat.

## Source positions

`reading/source_position.h` defines a layout-independent, versioned locator:

| Field | Meaning |
| --- | --- |
| `version` | Source-locator version, currently 1. |
| `href` | Normalized archive-relative content-document path. |
| `cfi` | EPUB CFI point with package/spine and content-document steps. |
| `offset` | UTF-16 offset in the content document's source-text stream. |
| `before`, `after` | Bounded source context immediately around the point. |

The Qt boundary validates field types, version, paths, numeric CFI syntax and
size limits. A locator is limited to 4096 UTF-8 JSON bytes, its CFI to 2048 UTF-16
units, and each context field to 64 units. Internal navigation carries the
object in a validated `kobalt-source:1:` token. It is never interpreted as a
CREngine XPointer or a Kobo-native position.

The design follows [EPUB CFI 1.1](https://w3c.github.io/epub-specs/epub33/epubcfi/).
Package steps follow the actual OPF element order. Content steps count elements
and inter-element character data; character offsets use UTF-16 and do not split
surrogate pairs. The supported subset covers numeric point CFIs and
object/element points. CFI ranges, ID assertions and embedded CFI text assertions
remain unavailable. Supplementary JSON context uses the helper's source-text
stream; it does not claim CFI's whitespace-normalization semantics for embedded
assertions.

The helper verifies the structural point against its context. If that fails,
it can use a verified text offset or a unique matching context. Missing and
ambiguous text is rejected rather than guessed. `LOCATE` adds a spine index and
base64-encoded locator JSON to `KWRP/1`. Malformed, unsupported and unresolved
requests restore the previous page and report an error without exiting.

The proxy retains the logical source point through pagination, typography and
viewport changes. Reflow displays its containing page while retaining the
original point, avoiding backward drift to a new page's earlier first
character. A page turn records the new page's source point. Sleep restarts and
cold openings use this same restoration path. The resource path and package
CFI distinguish repeated spine entries that use the same content file. Helper
URLs and DOM objects are not persisted.

## Saved-data compatibility

WebKit checkpoints use the optional `backend_positions.webkit` book-state slot.
It contains a `fingerprint` and a `position` locator. Its content fingerprint is
independent of the legacy top-level fingerprint, so a new WebKit checkpoint
does not relabel an older CREngine DOM. A mismatched publication never restores
that slot. Explicit restart starts at the beginning.

Checkpoints preserve CREngine's position, DOM version, fingerprint, appearance,
native reconciliation and unknown fields. Other backend slots and unknown
supported locator/slot fields survive edits. A missing `nickel_progress`
baseline is initialized from the observed native state when available; an
existing baseline is preserved. This prevents an unchanged native Unread status
from discarding a new local checkpoint. Unsupported locator versions are not
overwritten. Matching unsupported saved locators fail WebKit opening and retain
the existing CREngine fallback.

Routine source checkpoints use the existing background record writer. Close
completion is asynchronous. Interactive GUI operations neither write storage
nor wait for a worker. These saves do not learn pace/history, write a native
position, enable KOSync or implicitly save global appearance. Book-record
format 1, preference schema 1 and database schema 3 stay unchanged. See
[Storage compatibility](../storage.md).

There is no validated CFI/XPointer/native conversion yet. The backends retain
independent positions. Older writers' preservation of this optional field
depends on their book-state handling.

## Chapters

The helper exports EPUB 3 navigation and EPUB 2 NCX nesting depths. The proxy
resolves destinations on the document worker into source locators, exact layout
pages and depths. Duplicate destinations remain separate rows. A missing
fragment omits the broken destination while leaving the publication readable.

The existing `Reader::showChapters`, `ChapterContents` panel, shared rows,
metrics, typography and paging controls present these entries. No Qt control or
styling changes are introduced. Selection follows source order. Shared-page
destinations retain the containing page in the preceding chapter's extent.
Reflow refreshes page numbers and selection.

TOC resolution is eager, alongside M3's spine pagination. Avoiding full-page
renders for location queries remains later optimization work; this slice makes
no startup-performance claim.

## Verification and limits

See [M4 results](m4-results.json) for current results and evidence. The native
proxy regression covers validation, cold restoration, reflow, TOC
fragments/depths/duplicates, asynchronous saves, independent fingerprints and
saved-data preservation. Existing CREngine, session, storage and main-thread
checks remain in their normal lanes.

The standalone helper diagnostic checks real DOM CFI restoration, Unicode
context, unique-text recovery and nonfatal rejection. The production ARM
session diagnostic checks TOC navigation, reflow and cold reopening through a
saved profile record. The installed diagnostic checks the actual NickelHook
reader, Chapters entry/opened screen, backend switching and saved reopening.
These use explicit unsandboxed experiments with offline network restrictions.
They do not validate physical sandbox behavior or device performance.

Build/check both prepared Kobo SDKs and the helper as documented for M3, then
use the existing firmware runner's `--epub-only`, `--session-only` and
`--installed-only` actions with `--allow-unsandboxed-experiment`. The installed
action requires the Qt6 diagnostic package. Disposable devices are removed
after each run. At the user's request, the retained manual device
`kobalt_webkit_m3_manual` was subsequently upgraded to this M4 slice. Its books
and settings were preserved, and its profile, native data, mod and helper were
backed up while stopped. The existing restart script retains the runtime
configuration. The helper remains outside scanned onboard storage.

The targeted screen review is in `build/review/webkit-m4/`, using captures from
`build/screenshots/webkit-m4/`. It compares the Chapters entry and opened list
with CREngine, and the restored WebKit page with its pre-close frame. Those two
reader captures are pixel-identical. Serve it with
`node platforms/review/review.mjs serve --data build/review/webkit-m4 --port 8765`.
Only the user records seen status and visual feedback.

Reading statistics, advanced typography and writing directions, and validated
native/XPointer conversion remain M4 work. The complete gate also requires
broader automated coverage of pointer editing, continuation and recovery.
