# M3 initial Kobalt integration

The initial integration slice was committed as `45069da`, based on M2
(`92eb5f7`), on `feature/webkit-wpe-m3`. It implements backend selection,
production session integration and a firmware diagnostic. CREngine remains the
default. The user approved committing this slice and continuing M3. M4 and
release publication remain separate review gates.

## Document and session ownership

`reading/document.h` contains the worker-owned document contract consumed by
`ReaderSession`. Shared result types moved out of the CREngine class header.
`EngineDocument` implements the contract using its existing methods. Its native
position codec, parser, fonts, caches and annotation implementation stay intact.
The two adapter methods handle the existing CREngine preview and platform
chapter resolver. Optional features have unavailable/empty defaults for the
experimental backend; they do not attempt to interpret CREngine XPointers.

`engine/webkit/WebKitDocument` is a Qt-only proxy. WPE, GLib and the private C++
runtime stay in the supervised helper. The proxy uses the existing serialized
document worker. Process startup, IPC waits, mapping, copying and process cleanup
never run on the interactive GUI thread. Blocking operations use the existing
main-thread guard. No new threads, RPC framework or application build runner
were introduced.

Existing session revisions and source leases continue to guard published
`ReaderFrame` copies. Superseded layouts are discarded before presentation.
Revoking/cancelling the source interrupts a proxy wait and terminates its
supervisor. WebKit does not run CREngine's neighbour-image preparation.

## Selection and fallback

`OpenRequest::backend` accepts `crengine` or `webkit`. An empty value consults
`KOBALT_READER_BACKEND`; an unset or unrecognized value uses CREngine. The
experimental selection applies only to accepted local `file://` identities.
Other publication identities retain CREngine. Normal publication inspection,
source authorization and layout inspection precede backend opening. The helper
also retains M2's independent archive/resource checks and encryption rejection.

A failed WebKit opening disposes its supervisor and tries CREngine with the same
authorized resources and original saved state. A cancellation or an earlier
publication/resource failure does not trigger that fallback. Later renderer
failures report through the session error field; automatic recovery belongs to
M4.

The launcher defaults to
`/mnt/onboard/.adds/kobalt-webkit/bin/kobalt-webkit`. Development overrides are:

| Variable | Meaning |
| --- | --- |
| `KOBALT_WEBKIT_LAUNCHER` | Absolute supervisor executable path. |
| `KOBALT_WEBKIT_MODE` | `required` (default), `experiment` or `device-unsandboxed`. |
| `KOBALT_WEBKIT_QEMU_PREFIX` | Explicit M1 supervisor `--qemu-prefix` argument for firmware diagnostics. |

No mode is inferred from the device or from sandbox failure. The existing
required-sandbox default remains. The firmware diagnostic explicitly selects
the unsandboxed experiment already documented in M1/M2, and retains the
simulator's offline network restrictions. It is not sandbox validation.

## Memory frames and navigation

The supervisor's optional `--memory-frames` flag requires tmpfs at `/dev/shm`.
Its private runtime, including raw frame storage and metadata, lives there.
There is no disk-backed fallback in this mode. The worker skips diagnostic PNG
encoding. The existing M2 file/PNG transport remains the default for standalone
diagnostics.

The proxy uses the existing versioned `KWRP/1` messages and frame metadata. It
requires the requested sandbox mode in the startup handshake and validates
request identity, protocol/frame versions, paths, dimensions, stride,
pixel format and regular-file size before mapping BGRA pixels. It copies the
mapped image into an owning `QImage` before sending `RELEASE`. A displayed frame
therefore survives the helper releasing its storage or exiting. No mapping
belongs to the GUI and no GUI callback performs synchronous IPC.

The current Qt interface needs a whole-book page count. The proxy measures each
spine entry at opening and after a layout change, then keeps page-count offsets
for that layout. It does not retain those entries' images. M2's description adds
linear-spine flags so page turns skip non-linear entries while explicit page/link
jumps can reach them. This eager measurement favors correct existing navigation
semantics; startup/reflow cost needs later measurement and optimization. It is
not a page-image cache or a performance claim.

Closing deletes the proxy on its owning worker. A WebKit session is not retained
as a closed-book CREngine cache. Sleep queues supervisor cleanup while retaining
the displayed frame and its in-memory chapter/page. The next rendering request
starts a fresh helper and restores that volatile location. Application shutdown
uses the existing worker drain and join.
Owners that outlive the worker close their helper synchronously inside an
explicit application-shutdown scope, when input has ended. They do not enqueue
cleanup on the destroyed Qt worker. The native regression retains a live proxy
through the worker join and checks both process cleanup and the main-thread
guard.

## Reading data and feature limits

M2's UTF-16 locations remain provisional. WebKit frames supply neither a
CREngine `position` nor `dom_version`. KOSync digests, native reading writeback,
implicit appearance saves, reading-history learning and book checkpoints are
disabled for experimental WebKit reading. Existing supported book records and
preferences are preserved. The native regression exercises opening, turning,
checkpointing and closing against a pre-existing record, including unknown
fields. No storage schema or cache format changed.

WebKit reading progress is **not persisted** by this slice. Persistent positions,
native conversion, selection/annotations, search, previews, complete TOC and
advanced appearance remain M4. The initial proxy exposes the M2 publisher and
generic-family modes, font size, line spacing, margin, word spacing and theme.
Custom CSS, custom font catalog integration and the remaining Qt typography
controls are not implemented for WebKit yet.
The initial proxy uses the archive basename as its title and does not yet supply
author metadata or a publication cover.

The firmware captures verify pixel transport and stable navigation, not visual
parity. Inspection of the Type Tester's title pages shows oversized publisher
text crossing columns. That layout limitation is not fixed by this integration.
The actual Nickel-hosted Kobalt window, end-to-end installed-mod sleep/shutdown,
physical sandbox behavior and physical-device display performance remain review
work. The firmware diagnostic links the production session objects but does not
load Kobalt as a NickelHook plugin.

## Verification

See [M3 results](m3-results.json) for commands and current evidence. The native
proxy regression uses a controllable helper to test navigation, pixel ownership,
frame rejection, cancellation, restart, data preservation and CREngine fallback.
Existing native CREngine and lifecycle tests remain in their normal lanes.

The standalone helper sources under `src/webkit/` are excluded from the Kobo
and Android application globs. The Qt proxy stays under `src/engine/`, so those
applications compile it without linking WPE into Nickel or Qt.

Build the existing Kobo test targets, then run the focused firmware diagnostic:

```sh
bash platforms/kobo/build.sh qt6 --check
bash platforms/webkit/build.sh
python3 tests/webkit/run-firmware.py \
  --virtualnickel /home/sherman/kobo-dev/VirtualNickel \
  --allow-unsandboxed-experiment --session-only
```

The Qt6 `kobo-tests` target builds `kobalt-webkit-session-check` from the same
production objects as the mod. It is not registered as an SDK-only CTest test,
because it requires the independently deployed WPE bundle and firmware runtime.
The existing Device API runner deploys it to a disposable firmware 6 device,
checks navigation/resize/sleep and GUI heartbeat delivery, captures page images,
checks Nickel responsiveness and shared-memory cleanup, then removes the owned
device and volume. No simulator source or existing user device is modified.

claiming the entire milestone's review gate.
