# M1 build and runtime component

This M1 development candidate separates the renderer from the M0 investigation
without changing the Qt application, CREngine or reading data. The
[review record](m1-review.json) collects the build, deployment, lifecycle,
reproducibility and audit evidence. It is not a release package or an EPUB backend.
Published Kobo configs disable namespace support, so default sandbox operation
cannot be assumed on devices. The authorized `--allow-unsandboxed-device` opt-in
provides an explicit development mode. See [sandbox compatibility](sandbox.md)
for evidence, policy and the running-device diagnostic.

`dependencies/webkit/` owns pins, patches, toolchains and recipes. It uses the
existing verified downloads, locking and publication in `dependencies/cache.cmake`.
`platforms/webkit/` owns the standalone CMake project, container invocation and
packaging. `src/webkit/` contains the separate libc supervisor and WPE worker;
the application does not link them.

## Build

Use x86-64 Linux, CMake 3.22 or newer, Podman and the existing prepared ARM image
whose exact content ID is in `dependencies/webkit/build-image.json`. Kobalt
application builds continue to use kobuild. The script accepts the pinned local
image only and does not install or pull it. An exact OCI recovery archive is pinned separately in
`platforms/webkit/sdk-archive.json`. The archive preserves the prepared environment;
it does not rebuild Qt or select new packages. Reconstructing the image from raw
package inputs remains distinct from restoring this archived image. The old
moving-repository Containerfile cannot reproduce it.

Run from this feature worktree:

```sh
bash platforms/webkit/build.sh
# Optional compiler parallelism; it does not change the dependency identity:
KOBALT_WEBKIT_JOBS=8 bash platforms/webkit/build.sh
```

The wrapper registers with the existing performance-evaluation lock and honors
`KOBALT_DOCKER_CPUS` when set; compiler parallelism remains `KOBALT_WEBKIT_JOBS`.
The container has no network and a read-only root. Only this worktree, the shared
cache and temporary storage are writable. Verified archives must be cached first.
For missing archives, explicitly run `cmake -P dependencies/webkit/prepare.cmake`
with network access before building. Tools are verified and extracted into this
worktree's `build/webkit/tools/`. No tools or runtime assets come from another
worktree. The host CMake requirement is the same as ordinary application builds.

The dependency key includes the prepared image ID, CMake version, pins, recipes,
toolchains, patches and shared cache helpers. A successful install alone publishes
`complete`; interrupted builds resume under the existing lock. Published entries
are never changed. Both M0 CPU patches remain. A third patch permits
`WEBKIT_EXEC_PATH` in release builds without enabling developer mode. The launcher
sets that path after clearing the environment. A fourth patch refuses child
startup when a requested sandbox is unavailable, instead of using upstream’s
unsandboxed fallback. The worker grants read-only access
to the installed bundle using WebKit's public sandbox-path API.

`build/webkit/dependency-entry.txt` selects the completed dependency set, and
`build/webkit/bundle.txt` selects the package. Paths use `/work` and
`/dependency-cache` inside containers. Objects and packages stay in this worktree.

## SDK recovery and corresponding sources

These explicit commands use the same shared download cache. Nothing is pulled
or restored automatically by an ordinary build:

```sh
cmake -DACTION=VERIFY -P platforms/webkit/sdk-image.cmake
cmake -DACTION=RESTORE -P platforms/webkit/sdk-image.cmake
cmake -DACTION=FETCH -P platforms/webkit/sources.cmake
cmake -DACTION=EXPORT -P platforms/webkit/sources.cmake
```

`EXPORT` for `sdk-image.cmake` creates a candidate recovery pin from the exact
installed image. `VERIFY` checks the reviewed archive SHA-256, OCI manifest/config
identity and architecture. `RESTORE` explicitly loads it only when that image is
missing. `ARCHIVE` selects a supplied archive; otherwise the pinned copy in the
shared download cache is required. Local image recovery is separate from public
SDK redistribution, which would require its own complete distribution material.

Build the renderer before exporting its sources, so the export can check the
actual runtime library mapping. The source fetch uses `runtime-sources.json`, derived from signed Ubuntu snapshot
metadata and the exact compiler recipe commits in `source-provenance.json`.
It retains Ubuntu source descriptors, pristine archives and Debian patches, plus
GCC, crosstool-NG and koxtoolchain sources. The toolchain's embedded configuration
and build log identify the GCC patches. SHA-256 is checked on every use. Fetching
is explicit; exporting refuses uncached or changed inputs and checks the binary
package/source-version mapping against the actual renderer package.

The source tar contains the standalone application sources, patches, fixture,
notices, corresponding archives, provenance and checksums. Ubuntu source groups
retain filenames required by `dpkg-source`. Binary SDKs/toolchains are separate
pinned build inputs and are not included in this source artifact. Supply the
prepared image and verified kobov5/CMake binary archives separately for offline
building. A complete enabled-source license/ISA audit is still a release gate.

Verify a pristine extracted source bundle with `ACTION=VERIFY` and an absolute
`SOURCE_BUNDLE` path. Building its `application/` directory automatically imports
the WebKit archive from the enclosing bundle before any dependency-cache hit is
used. `KOBALT_WEBKIT_SOURCE_BUNDLE` selects another supplied bundle explicitly.
Imports validate all declared third-party archive hashes but allow the recipient
to modify application sources and patch recipes. Full verification also checks
the pristine first-party checksums.

## Package and lifecycle

The selected package directory contains `kobalt-webkit-armhf.tar`, with one
`kobalt-webkit/` directory. Extract into a development deployment directory such
as `/mnt/onboard/.adds/`. Verify `SHA256SUMS` inside the installed directory.
Launch `bin/kobalt-webkit` using pipes for standard input/output. Do not preload
Nickel's libraries into the supervisor. A future Qt caller must use a clean
environment and asynchronous process APIs; this slice adds no reader caller.

The package includes the supervisor, worker, libc-only platform diagnostic,
WebKit's mandatory Web/Network processes,
the injected bundle, the recursive private ELF closure and the fixed fixture.
Private libraries use regular files named by SONAME, avoiding symlink requirements
on Kobo's FAT user storage.
Packaging rejects host ELFs, incorrect ARM calling convention/interpreter and
glibc requirements above 2.35. It excludes the firmware libc/loader family and
strips copies alone. Input hashes, an ELF report, exact build/source-package
versions, notices and output checksums accompany it. Tar entries are sorted,
with numeric root ownership and a pinned timestamp. An independent offline
rebuild from the exported source and a restored SDK produced identical installed
files and the original runtime tar before the sandbox correction. The prepared SDK/compiler binaries remain
locked inputs; this test does not rebuild them.

The supervisor uses libc alone. It closes inherited descriptors, clears the
worker environment and creates a private run directory. It owns a process group
and acts as a child subreaper. On shutdown, disconnect, signal or worker failure,
it terminates/reaps children, including adopted children in separate sessions,
then removes the run directory. Worker failures become process exit statuses.
Termination escalates after one second; cleanup has a five-second deadline.
SIGKILL of the supervisor itself cannot promise complete cleanup; the future
owner must provide a fallback process-tree policy.

Normal startup requires WebKit's compiled-in sandbox. An additional probe found
that upstream automatically disabled it inside an unsupported container, even
without the explicit override. The fourth patch makes this path fail before
spawning an unsandboxed child. `READY sandbox-required` identifies the requested
policy, not a verified isolation result. The supervisor disables core dumps.
The explicit
`--allow-unsandboxed-experiment` option selects the approved simulator experiment.
The separately authorized `--allow-unsandboxed-device` option selects device mode
and reports `READY device-unsandboxed`, with a diagnostic on stderr. Both disable
WebKit's internal sandbox for that invocation only. Inherited variables cannot
select either mode; conflicting flags and inconsistent worker inputs are rejected.
`--qemu-prefix /firmware/rootfs` explicitly launches the ARM worker while preserving the guest
prefix for WebKit's children. The packaged ARM supervisor supports child reaping
under QEMU. Physical-device sandbox operation remains unverified. No simulator sources or normal
container/network restrictions change.

## Asynchronous protocol

Dedicated pipes carry bounded ASCII lines. Stderr carries diagnostics and stdout
carries protocol only. Requests contain `KWRP/1`, an increasing positive unsigned
ID and a command. ID zero is reserved for startup/fatal errors. Version mismatches,
duplicate IDs and oversized requests end the connection. Lines are bounded to
256 bytes and the nonblocking output queue to 64 KiB. Shutdown drains output for
at most two seconds. EOF closes the worker.

```text
< KWRP/1 0 READY sandbox-required
> KWRP/1 1 PING
< KWRP/1 1 OK PONG
> KWRP/1 2 RENDER 800 1100
> KWRP/1 3 PING
< KWRP/1 3 OK PONG
< KWRP/1 2 OK SNAPSHOT 800 1100 /tmp/kobalt-webkit-XXXXXX/snapshot.png
> KWRP/1 4 SHUTDOWN
< KWRP/1 4 OK BYE
```

`RENDER` loads only the packaged trusted fixture, at 100–2048 pixels per dimension.
One render can be active; another returns `ERROR busy`. Each render has a
60-second deadline. Copy the diagnostic PNG before the next capture overwrites
it or shutdown deletes it. A render failure reports a stable code, logs the
underlying diagnostic and ends the worker. Starting a fresh helper is the current
recovery boundary. EPUB loading, book-script isolation, pagination and owned
pixel-buffer IPC remain later work. This file path is not a production frame
lifetime contract.

## Verification

The standalone CTest project exercises environment/descriptor isolation, process
ownership, failures, signals and cleanup:

```sh
cd platforms/webkit
cmake --preset native-supervisor
cmake --build --preset native-supervisor
ctest --preset native-supervisor
```

The [first result record](m1-results.json) captures the first implementation
slice. The ARM build, native supervisor checks, package-integrity checks and tar
reconstruction passed. The installed ARM launcher/worker passed rendering,
resize, asynchronous ping, protocol rejection, EOF, backpressure, WebProcess and
worker crashes, post-crash restart and cleanup in firmware 6.0.274403. Nickel
remained responsive. The visually inspected fixture matches M0 byte for byte;
process maps contain no GPU/multimedia modules. The corrected run has no GLib
critical messages. Its disposable device and system volume were deleted.
These are QEMU results with the approved internal-sandbox exception, not physical
hardware or production sandbox validation.

The [reproducibility result](m1-reproducibility.json) records the follow-up source,
SDK recovery and independent rebuild checks. New source/recovery regression tests,
real warm-cache source rejection and the focused crypto ISA diagnostic passed.
That reproducibility record covers the package before the sandbox correction.
The corrected ARM build and fresh firmware diagnostic passed rendering, protocol,
crash/restart, cleanup and normal-mode sandbox refusal. The normal-mode test
exited with status 133 and no snapshot; the experimental snapshot still matches
M0. Nickel remained responsive, and the disposable device and volume were deleted.
The standalone tests also passed with the core-dump limit assertion. The subsequent current-patch rebuild in the [review record](m1-review.json)
started from an empty compiled cache and reproduced the installed WebKit tree,
helpers and original device-mode tar byte for byte. The SDK/compiler and Ubuntu
runtime libraries remain locked binary inputs, not independently rebuilt SDKs. See the [source and distribution audit](source-audit.md)
for provenance, delivered material and remaining review gates.

When the host lacks GCC/Ninja, run these commands offline in the prepared native

## M1 review and limits

The [selected-configuration source/notice audit](source-audit.md) and
[runtime-resource audit](runtime-resources.md) are complete for this fixed
fixture and build. The [inventory](distribution-inventory.json) binds the actual
shared-library closure and enabled bundled components to corresponding source
archives and exact notice texts. Packaging retains header-only terms, required
acknowledgements and the correct pinned Instrument Serif notice. Pair the binary
with the complete matching source export and its checksums/replacement scripts.
This development packet does not authorize release publication or SDK redistribution.

Build, installation, protocol/rendering, crashes/restart and cleanup have been
verified in firmware 6 userspace through VirtualNickel, with the explicit modes
recorded in the results. The current WebKit patch set was independently rebuilt
offline with no compiled WebKit/helper objects copied; its install tree and
original runtime tar are identical. The corrected notice-only packet retains the
same runtime binaries. The artifact association next to the final source tar
records its current binary/source pairing.

The candidate still has these limits:

- Stock kernel configs disable sandbox features. Default startup requires the
  sandbox and refuses an unavailable one. The user-approved device opt-in is
  explicit; required-mode target Bubblewrap/D-Bus proxy packaging and actual
  isolation remain unverified.
- The font-resource audit used selected stock firmware resources. Other firmware
  font sets can produce different fallback images. Optional WebKit resource paths
  and networking/language features need their own validation when implemented.
- Physical-device ABI/kernel behavior, storage costs and e-ink performance remain
  later validation. QEMU results do not establish those properties.
- The SDK recovery archive restores the exact prepared environment. Rebuilding
  the entire SDK from raw inputs or publishing it is separate work.

Reader integration and M2 work are excluded. Stop at this M1 candidate for user review.
