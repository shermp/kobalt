# WPE-M5.1 Blaze integration seam

Proposed host base is `feature/blaze-engine` at `55870b001b401cb52b73bac53dedb0c39c269fe9`. The fork and upstream advertised that same SHA after synchronization. The WPE base on `feature/webkit-snapshot-engine` is `8f35f7c8ebd7c38bebb08d48fb101eecde5ca20a` (committed M4.3). A dry-run merge reported one file conflict in `src/publication/publication.cpp` at the embedded-font read. Integration needs Blaze's host font limit and M4.1's package-derived Adobe key, with admission regressions rerun against the resulting source.

## Implemented interfaces

| Area | Flow at the proposed Blaze base |
| --- | --- |
| Engine | `src/engine/engine.h` is a synchronous engine-worker interface. `createEngine()` in `engine_document.cpp` constructs the koblaze `EngineDocument`. The methods include parsed-book caches, previews, native positions and geometry that the WPE runtime does not supply. |
| Open and publication registration | Kobo's `ReaderCoordinator` owns `NativePublication` and creates a fresh `SourceLease`; standalone opens a local `PublicationEndpoint`. Both pass the lease and a `ResourceFactory` in `OpenRequest`. `runOpening()` inspects the materialized archive, fingerprints it, resolves saved appearance, binds the worker-owned cache and opens or rebinds the engine. M4.1 `WebResources` can scope the same inspected publication and cache to that lease. |
| Turn and reflow | `ReaderSession::turn()`, `resize()` and appearance changes feed the session's revision and pending-intent handling. `dispatch()` runs mutation and `capture()` on the worker. On the GUI thread the current lease and revision gate frame publication; `updated` invokes `Reader::refresh()`, and `paintTurn()` owns presentation and Kobo refresh policy. First frame has a separate typed `OpeningResult` callback. |
| Page and source state | `PageInfo` in `engine/query.h` carries zero-based page queries, a basis for estimates and a layout generation. Current session getters still read legacy frame JSON, including rough pages, so returning `PageInfo` alone has no UI effect. Blaze's `Location` v1 is shared and source-relative. The engine position string and Nickel `PositionCodec` are separate contracts. |
| Retirement | Cancellation and revocation end `SourceLease` access. Kobo's `drainReadingJobs()` and standalone's `ReaderSession::drain()` defer destruction of the publication endpoint. The current drain is a queued engine-worker barrier. A renderer reply or a resource read initiated by one can outlive that barrier. |

## Proposed seam for M5.2

1. Add one opt-in WPE path at `ReaderSession::open()` and `dispatch()` using a concrete `src/engine/webkit/` adapter. Factor out the existing GUI completion tails for first-frame and subsequent-frame publication. Keep the synchronous koblaze worker path and default engine. Reuse the host-only part of `OpeningJob` for inspection, admission, fingerprint, metadata, and opening resources before handing the scoped source to WPE.
2. Submit open, relative turn and supported reflow settings over the existing event-driven socketpair client. A terminal result returns a validated leased `QImage`, typed `PageInfo`, shared `Location` with restoration quality and applied settings, or an opening/render failure or boundary. Match the wire request and document/layout/pool generations before acquiring the image, then match the session's active operation, revision and lease before presenting it. Only the matching active operation may clear busy. On supersede, drain the old terminal result before sending coalesced work. If it committed in the child without being presented, apply the next intent from the last presented anchor so a buffered tap cannot skip a page. Failed or stale work leaves the displayed frame and checkpoint intact.
3. Expose capabilities through `ReaderSession` for WPE and guard the matching UI and idle-job entry points, including frame markup completion. Start with read-only rendering, local turns across admitted spine items, viewport changes and supported appearance. Suspend WPE actions that require previews, geometry, search, unimplemented navigation or a native checkpoint. Keep its source anchor in memory for reflow. Carry `PageInfo` with the published frame and use its readiness for WPE display. Map a measured spine-item count to exact local pages, absent global values to pending, and byte-based estimates to `ReadyEstimated` with `QueryBasis::Bytes`. Keep legacy local turn fields separate from book progress. Existing bookmarks, native saved data and cross-engine persistence are M6 work.
4. Extend the existing drain contract for WPE. Retirement revokes the source, stops new work and waits asynchronously for pending reads, the socket and process-tree teardown, including renderer failure. Release the host endpoint after both the worker and renderer activity have drained. Qt-held frame mappings still follow the image lease lifetime. The color transport fixture and retained EPUB renderer are separate today; M5.2 must connect them and add scoped resource request/reply on the existing bounded wire.

M5.2 validation should build the Qt5 and Qt6 variants, run open, turn, resize/font reflow and close through Kobalt on VirtualNickel FW4, and check superseded frames, close during a resource read, renderer death and the existing default-engine regression suites. M5.1 was a source and merge-base review.
